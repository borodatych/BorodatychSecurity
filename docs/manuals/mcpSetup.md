# ПОДКЛЮЧЕНИЕ MCP

MCP-сервер Borodatych Security даёт агенту те же проверки, что у CLI. Он только читает сервер и сайт:
ничего не меняет, не ставит и не перезапускает. Правки агент делает обычными своими инструментами
и только после согласия пользователя.

Что понадобится:

- Node.js 20 или новее и `npx`
- агент с поддержкой MCP: Claude Code, VibeIDE, Cursor или любой другой клиент
- для полной проверки сервера — права root (без них часть проверок скажет «не проверить»)

## Шаг 1. Проверить, что CLI работает

```bash
npx -y @borodatych/security --version
npx -y @borodatych/security --help
```

Одна проверка без установки:

```bash
sudo npx -y @borodatych/security --only ssh.auth
```

Если эта команда работает, MCP-сервер тоже запустится: это тот же пакет с подкомандой `mcp`.

## Вход и доступ к домену

Проверки `audit_server`, `audit_site`, `list_checks`, `explain_check` и `get_recipe` бесплатны и
работают без входа. `fix_plan` и `verify_fix` требуют доступа к домену: три домена бесплатно,
дальше — пропуск в кабинете на сайте.

Войти один раз в терминале:

```bash
npx -y @borodatych/security login
npx -y @borodatych/security whoami
```

`login` покажет код и ссылку, откроет браузер (если может), дождётся подтверждения и сохранит токен
`bsec_…` в `~/.config/borodatych-security/token` с правами `600`. `whoami` покажет email, остаток
бесплатных доменов и сроки пропусков; `whoami --json` отдаёт то же машинно.

MCP-клиент запускается от вашего пользователя и сам найдёт файл токена. Если клиент работает в
другом окружении или файла нет, передайте токен переменной `BOROSEC_TOKEN` в конфиге:

```json
{
  "mcpServers": {
    "borodatych-security": {
      "command": "npx",
      "args": ["-y", "@borodatych/security", "mcp"],
      "env": { "BOROSEC_TOKEN": "bsec_…" }
    }
  }
}
```

Не кладите токен в репозиторий. Если доступа нет, `fix_plan` и `verify_fix` вернут текстом, что
сделать: войти командой `login` или открыть кабинет `/my/checks` и оформить пропуск. Отозвать токен
можно там же, в блоке «Токены для CLI и MCP».

## Шаг 2. Подключить

### Claude Code

Одна команда:

```bash
claude mcp add borodatych-security -- npx -y @borodatych/security mcp
```

Проверить список серверов:

```bash
claude mcp list
```

Полезные варианты:

```bash
# только для текущего проекта (конфиг .mcp.json в репозитории)
claude mcp add --scope project borodatych-security -- npx -y @borodatych/security mcp

# для всех проектов пользователя
claude mcp add --scope user borodatych-security -- npx -y @borodatych/security mcp
```

После добавления перезапустите Claude Code (в текущей сессии достаточно команды `/mcp`,
чтобы увидеть сервер и его инструменты).

### VibeIDE

1. Откройте настройки MCP-серверов: «Settings → Tools → MCP» (название пункта зависит от версии;
   ищите раздел MCP или Model Context Protocol).
2. Добавьте сервер вручную и укажите команду `npx`, аргументы `-y @borodatych/security mcp`.
3. Если в настройках есть JSON-конфиг, вставьте блок из раздела «Любой клиент» ниже.
4. Перезапустите IDE и проверьте, что в списке инструментов появились `audit_server`, `audit_site`,
   `explain_check`, `list_checks`, `fix_plan`, `get_recipe`, `verify_fix`.

### Cursor

Глобальный конфиг — `~/.cursor/mcp.json`, конфиг проекта — `.cursor/mcp.json` в корне репозитория.
Содержимое:

```json
{
  "mcpServers": {
    "borodatych-security": {
      "command": "npx",
      "args": ["-y", "@borodatych/security", "mcp"]
    }
  }
}
```

Затем: «Settings → MCP» → убедиться, что сервер включён (зелёная точка), при необходимости нажать
«Refresh». Инструменты появятся в режиме Agent.

### Любой клиент

Клиенту нужны команда и аргументы запуска. Вставьте в его конфиг `mcpServers`:

```json
{
  "mcpServers": {
    "borodatych-security": {
      "command": "npx",
      "args": ["-y", "@borodatych/security", "mcp"]
    }
  }
}
```

Если `npx` не находится (IDE запущена с другим `PATH`), укажите полный путь к Node и к `npx`,
например `/usr/local/bin/npx`. Вместо `npx` можно поставить пакет глобально и указать
`borodatych-security` с аргументом `mcp`.

## Шаг 3. Проверить подключение

Спросите агента:

> Покажи список проверок Borodatych Security.

Агент вызовет `list_checks` и вернёт 27 проверок с id, разделом, важностью и названием.
Если инструментов нет — перезапустите клиент и проверьте `claude mcp list` или лог MCP в IDE.

## Пример диалога

**Пользователь:** Проверь мой сервер.

**Агент** вызывает `audit_server` (все проверки, кроме сайта) и получает JSON-отчёт.

**Агент:** Нашёл 2 дыры и 3 замечания. Критично: SSH разрешает вход по паролю (`ssh.auth`),
и PostgreSQL слушает на всех адресах (`net.listen`). Ещё нет автообновлений безопасности.
Отчёт по каждой проверке — с полями `status`, `severity`, `findings`, `fix`.

**Пользователь:** Почини SSH и PostgreSQL.

**Агент:** предлагает конкретные правки: в `/etc/ssh/sshd_config` — `PasswordAuthentication no`,
`PermitRootLogin prohibit-password`; в конфиге PostgreSQL — `listen_addresses = 'localhost'`;
перезапуск служб. Показывает diff и спрашивает подтверждение.

**Пользователь:** Да, применяй.

**Агент** вносит правки своими инструментами, перезапускает службы и снова вызывает
`audit_server --only ssh.auth,net.listen`, чтобы убедиться, что стало `ok`.

Важно: сам MCP-сервер правок не делает. Он только читает и возвращает отчёт; изменения выполняет
агент после согласия пользователя.

Проверка сайта выглядит так же:

> Проверь сайт example.ru.

Агент вызывает `audit_site` с `domain: "example.ru"`. Домен — только имя хоста: без `https://`,
пути, порта и без IP. Проверка лимитов запросов шлёт 30 быстрых запросов, поэтому по умолчанию
выключена; включайте её (`ratelimit: true`) только если пользователь не против.

Починка по плану:

> Построй план починки для example.ru.

Агент вызывает `fix_plan` и получает упорядоченный план: сначала дыры (`fail`), потом замечания
(`warn`), внутри — по важности; у каждого шага рецепт под найденный стек. Если домен не открыт,
инструмент вернёт текст, что сделать: войти (`login`) или оформить пропуск в кабинете. После правок
агент вызывает `verify_fix` с id проверки и доменом и показывает `fixed: true` только тогда, когда
проверка стала `ok`.

## Права root

MCP-сервер запускается от того пользователя, от которого работает клиент. Без root проверки,
которым нужны `/etc/shadow`, `sshd -T`, `docker` и подобное, вернут `unknown` с подсказкой
«запустите с sudo» — это не провал, а «не проверить».

Запускать всю IDE от root не стоит. Разумный порядок: обычные проверки — через MCP, а полный
аудит — отдельной командой в терминале:

```bash
sudo npx -y @borodatych/security
```

## Если не работает

| Симптом | Что проверить |
|---|---|
| клиент не видит сервер | `npx -y @borodatych/security mcp` запускается в терминале и ждёт ввод |
| инструментов нет в списке | перезапустить клиент, включить сервер в настройках MCP |
| `npx: command not found` | Node.js 20+ установлен, `npx` есть в `PATH` клиента |
| проверки возвращают `unknown` | нет прав: запустить CLI через `sudo` для полного отчёта |
| `audit_site` ругается на домен | передать только имя хоста: `example.ru`, без схемы, пути, порта и IP |
| `fix_plan` или `verify_fix` просят войти | `npx -y @borodatych/security login` или `BOROSEC_TOKEN` в `env` клиента |
| «Бесплатные домены закончились» | оформить пропуск в кабинете `/my/checks` |

## Что доступно агенту

| Инструмент | Аргументы | Ответ | Доступ |
|---|---|---|---|
| `audit_server` | `only?: string[]`, `skip?: string[]` | JSON-отчёт как у `--json`, все проверки кроме `web.*` | бесплатно |
| `audit_site` | `domain: string`, `ratelimit?: boolean` (по умолчанию `false`) | JSON-отчёт по `web.*` | бесплатно |
| `explain_check` | `id: string` | что проверяет, как, что считается проблемой, чем чинить | бесплатно |
| `list_checks` | — | id, раздел, важность, название | бесплатно |
| `get_recipe` | `checkId: string`, `stack?: string`, `domain?: string` | шаги, конфиг, команда проверки и риски | бесплатно |
| `fix_plan` | `domain: string`, `ratelimit?: boolean` | план: только `fail` и `warn`, рецепты под найденный стек | нужен доступ к домену |
| `verify_fix` | `checkId: string`, `domain: string` | статус одной проверки сайта, `fixed=true` только при `ok` | нужен доступ к домену |
