# ПОЧИНКА САЙТА: FIX

`fix` — единственная команда пакета, которая меняет сервер. Проверки по-прежнему только читают.
`fix` правит конфиг веб-сервера, проверяет его, перезагружает службу и умеет откатиться.

Что нужно:

- Linux и root (запуск через `sudo`);
- вход в CLI и доступ к домену (`login`, `whoami`), как у `fix_plan` в MCP;
- nginx или Caddy v2 с конфигом в файле (`/etc/caddy/Caddyfile` для Caddy);
- домен в `--domain` — только имя хоста, без схемы и пути.

```bash
sudo npx @borodatych/security fix --domain example.ru --dry-run
```

## Что чинится само

| Проверка | nginx | Caddy |
|---|---|---|
| `web.headers` | HSTS `max-age=31536000; includeSubDomains` (без preload), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy-Report-Only` | то же в `header { }` |
| `web.banner` | `server_tokens off;` | `header -Server` |
| `web.sourcemaps` | `location ~* \.map$ { return 404; }` | `@maps path *.map` и `respond @maps 404` |
| `web.ratelimit` | `limit_req_zone` в `/etc/nginx/conf.d/borodatych-security-ratelimit.conf` и `limit_req` в server | только рецепт |

CSP всегда включается в режиме `Report-Only`: сначала смотрите отчёты, через неделю без нарушений
переименуйте заголовок в `Content-Security-Policy` руками. HSTS намеренно без `preload`.

Остальные проверки `fix` не меняет: печатает рецепт из каталога.

## Что увидите

1. **Аудит.** `fix` проверяет сайт снаружи. По умолчанию без `web.ratelimit`, потому что эта
   проверка шлёт 30 быстрых запросов. Хотите чинить только лимит — добавьте `--only web.ratelimit`.
2. **Дифф.** Один unified diff по каждому файлу и список «правка / пропуск».
3. **Подтверждение.** `Применить? [y/N]`. Без терминала и без `--yes` команда откажется работать.
4. **Бэкап.** Каталог `/var/backups/borodatych-security/<ISO-время>/` с правами `700`,
   копии файлов — `600`, полный путь файла повторяется внутри каталога.
5. **Применение.** Запись атомарная: временный файл рядом, затем `rename`; права и владелец
   исходного файла сохраняются.
6. **Проверка.** `nginx -t` или `caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`.
7. **Перезагрузка.** `systemctl reload nginx` / `systemctl reload caddy`; если `systemctl` нет —
   `nginx -s reload` / `caddy reload`.
8. **Перепроверка.** Через 5 секунд сайт проверяется снаружи заново по починенным проверкам.

## Если проверка конфига или reload не прошли

`fix` восстанавливает **все** изменённые файлы из бэкапа, удаляет созданные им файлы и выходит
с кодом `1`. Текст ошибки валидатора печатается. Ничего полуприменённого не остаётся.

## Если перепроверка не прошла

Правки **не откатываются**. Причины обычно снаружи сервера:

- перед сервером CDN или кэш (Cloudflare, nginx-прокси на другой машине) — обновите кэш;
- домен обслуживает другой сервер, а не тот, где вы запустили `fix`;
- приложение само перезаписывает заголовки (`add_header` внутри `location` отменяет наследование
  серверных заголовков в nginx — проверьте, нет ли такого блока).

Вывод покажет, какая проверка осталась в `warn`/`fail`, и подсказку про кэш или CDN.

## Откат

В конце работы `fix` печатает готовую команду:

```bash
sudo npx @borodatych/security fix --rollback /var/backups/borodatych-security/2026-11-07T12:00:00.000Z
```

Откат читает `manifest.json` в каталоге бэкапа, возвращает файлы, удаляет созданные `fix` файлы,
проверяет конфиг и перезагружает службу. Если конфиг после отката не проходит — команда скажет
об этом и выйдет с кодом `1`.

## Флаги

| Флаг | Что делает |
|---|---|
| `--domain <host>` | домен, который чиним; обязателен |
| `--only id,id` | только эти проверки; остальные не трогаем |
| `--yes` | не спрашивать подтверждение (для cron и агентов) |
| `--dry-run` | показать дифф и выйти, ничего не менять |
| `--json` | машинный итог: `ok`, `server`, `changes`, `skipped`, `recheck`, `rollback` |
| `--rollback <путь>` | откат по каталогу бэкапа |

## Безопасность

- Если блок конфига не удалось разобрать однозначно, файл не трогается, печатается рецепт.
- Если в блоке уже есть `add_header` того же имени или `server_tokens`, пункт пропускается
  с текстом «уже задано вручную, не трогаю».
- Чужой файл по нашему пути (сниппет без маркера `# borodatych-security`) не перезаписывается.
- Для nginx `ratelimit` не включается, если в `http` нет `include conf.d/*.conf`.
- Для Caddy `ratelimit` всегда только рецептом.
