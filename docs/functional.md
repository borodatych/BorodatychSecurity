# ВОЗМОЖНОСТИ

Каталог того, что продукт умеет сейчас. Статус на 07.11.2026, ветка `next`.
Список проверок — [checks.md](checks.md), подключение MCP — [manuals/mcpSetup.md](manuals/mcpSetup.md).

## 1. CLI сервера

- **Что:** проверяет защиту сервера изнутри: ОС, SSH, порты, сетевой экран, Docker, Fail2ban,
  CrowdSec, бэкапы — разделы 1–4 и 6 каталога проверок.
- **Как:** `sudo npx @borodatych/security` (полный отчёт требует root).
- **Итог:** текстовый отчёт в терминал; код выхода 1, если есть дыры.

## 2. Проверка сайта снаружи

- **Что:** проверяет сайт по домену запросами по HTTPS: утечки `.env` и `.git`, source maps,
  заголовки безопасности, TLS, CORS, cookie, лимит запросов, версии ПО — раздел 5.
- **Как:** `npx @borodatych/security --domain example.ru`; домен — только имя хоста.
- **Итог:** те же текстовый и JSON-отчёты; работает и с самого сервера, и с любой машины.

## 3. Текстовый отчёт по-русски

- **Что:** сводка «дыр N, стоит поправить N», список худших, затем проверки по разделам.
  У каждой находки — «что значит» и «чем чинить»; `ok` и `skip` — только факты.
- **Как:** запуск без `--json`.
- **Итог:** читается человеком без перевода терминов; в конце — строка про сайт с историей и
  слежением, `--quiet` её убирает.

## 4. JSON-отчёт

- **Что:** стабильная схема для агентов и скриптов: `version`, `host`, `startedAt`, `checks[]`
  с полями `id`, `section`, `severity`, `status`, `findings`, `fix`.
- **Как:** `npx @borodatych/security --json`.
- **Итог:** тот же отчёт отдаёт MCP-инструмент `audit_server` и `audit_site`.

## 5. MCP для агентов

- **Что:** тот же движок как MCP-сервер по stdio; агент сам запускает проверки и читает отчёт.
- **Как:** `npx @borodatych/security mcp`; подключение одной командой
  `claude mcp add borodatych-security -- npx -y @borodatych/security mcp`.
- **Инструменты:**
  - `audit_server` — проверки сервера, кроме `web.*`, с фильтрами `only`/`skip`;
  - `audit_site` — проверки `web.*` по домену, `ratelimit` по умолчанию выключен;
  - `explain_check` — что проверяет, что считается проблемой, чем чинить;
  - `list_checks` — id, раздел, важность, название.
- **Итог:** агент объясняет находки и предлагает правки; применяет их только после согласия
  пользователя, сам MCP-сервер ничего не меняет.

## 6. Выбор проверок

- **Что:** запустить только нужные проверки или пропустить лишние по id из каталога.
- **Как:** `--only ssh.auth,net.listen`, `--skip web.ratelimit`; в MCP — аргументы `only`/`skip`.
- **Итог:** неизвестный id — понятная ошибка со списком, а не молчаливый пропуск.

## 7. Коды выхода

- **Что:** 0 — дыр нет, 1 — есть хотя бы одна дыра, 2 — ошибка CLI (флаг, id).
- **Как:** код возвращает команда CLI.
- **Итог:** годится для cron и CI: «есть дыры» отличается от «не смогли проверить».

## 8. Только чтение

- **Что:** инструмент ничего не меняет на сервере: не ставит пакеты, не правит конфиги,
  не перезапускает службы, не ходит в интернет без запроса.
- **Как:** обещание в CLI и MCP; команды запускаются через один исполнитель с таймаутом.
- **Итог:** проверку можно запускать на живом сервере без риска.

## 9. Секреты не печатаются

- **Что:** значения из `.env`, ключи и пароли в отчёт не попадают; находки redacted.
- **Как:** общий фильтр секретов на всех находках.
- **Итог:** отчёт можно показывать и прикладывать к заявке.

## 10. Честные «не проверить» и «неприменимо»

- **Что:** нет команды или прав — `unknown`; нет Docker, NPM или это не Linux — `skip`.
- **Как:** итог каждой проверки — `ok`, `warn`, `fail`, `skip`, `unknown`.
- **Итог:** отсутствие прав не выглядит как дыра, а реальная дыра не теряется.

## 11. Каталог проверок и справка

- **Что:** 27 проверок в 6 разделах; у каждой — id, важность, что проверяет, что считается
  проблемой, чем чинить.
- **Как:** [checks.md](checks.md); в MCP — `list_checks` и `explain_check`.
- **Итог:** код и документация не расходятся — это сверяет тест.

## 12. Установка и сборка

- **Что:** запуск без установки через `npx`, глобальная установка, сборка одним файлом для Node 20+.
- **Как:** `npx @borodatych/security`, `npm i -g @borodatych/security`, `bun run build`.
- **Итог:** на сервере не нужен Bun — достаточно Node 20+.

## 13. Рецепты починки

- **Что:** к каждой из 27 проверок — подробная инструкция: шаги, готовый фрагмент конфига под стек
  (nginx, Caddy, Apache, Nginx Proxy Manager, Traefik, Cloudflare, Express, Next.js) и команда проверки;
  для сайта — стартовый CSP по собранным ресурсам.
- **Как:** `@borodatych/security/recipes`: `getRecipe(id)`, `renderRecipe(recipe, { domain, csp })`,
  `pickVariant(recipe, stacks)`; стек определяется по заголовкам через `detectStack`.
- **Итог:** сайт, CLI и MCP берут тексты из одного источника; рецепты только описывают правки и ничего
  не применяют.

## 14. Вход в CLI и MCP

- **Что:** вход по коду устройства через браузер, как `gh auth login`: команда просит код, человек
  подтверждает его на сайте, команда сохраняет токен `bsec_…`.
- **Как:** `npx @borodatych/security login`; `whoami` показывает email, остаток бесплатных доменов и
  пропуска, `--json` отдаёт тот же ответ машинно; `logout` удаляет токен.
- **Хранение:** `~/.config/borodatych-security/token` с правами `600`, каталог — `700`;
  `BOROSEC_TOKEN` важнее файла; под `sudo` берётся домашний каталог `SUDO_USER`.
- **Итог:** токен не печатается в отчёт и не попадает в репозиторий.

## 15. MCP-инструменты починки

- **Что:** `fix_plan` — упорядоченный план по домену: только `fail` и `warn`, сначала дыры, внутри —
  по важности; у каждого шага рецепт под найденный стек. `get_recipe` — рецепт по id проверки
  бесплатно и без входа. `verify_fix` — повторная одна проверка сайта после правки, `fixed=true`
  только при `ok`.
- **Как:** через MCP. `fix_plan` и `verify_fix` бесплатны для трёх доменов, дальше нужен пропуск в
  кабинете; без входа инструмент возвращает понятный текст, что сделать человеку.
- **Итог:** агент ведёт от находки к починке и самопроверке, но ничего не меняет за пользователя.
