# FIX: ЧТО ПОКАЗАЛИ НАСТОЯЩИЕ NGINX И CADDY

Стенд `bun run stand` проверяет `fix` на `nginx:1.27.3-alpine` и `caddy:2.8.4-alpine`,
а не на подменах. Ниже — ошибки, которые нашлись только на живых серверах.

## nginx: add_header в location отменяет наследование

Если в `location` есть хотя бы один свой `add_header`, nginx не наследует `add_header` из
`server`. Сниппет `fix` лежал на уровне server и в такой location просто не работал:
`nginx -t` проходил, а HSTS и остальных заголовков в ответе не было.

Решение: кроме основного сниппета `borodatych-security.conf` появился
`borodatych-security-headers.conf` — только заголовки. Его `include` вставляется внутрь каждого
`location` с собственным `add_header` в том же файле, что и server-блок. `location` из
подключённого через `include` файла сканер не видит: это остаётся ручной проверкой.

## Caddy: матчер @maps может быть занят сайтом

Сниппет объявлял `@maps path *.map`. Если в блоке сайта уже был свой `@maps` (например, для
`/health`), Caddy отвечал `matcher is defined more than once: @maps` — `caddy validate` падал,
и `fix` откатывался. Заодно проверка «sourcemaps уже настроены» реагировала на любое имя `@maps`,
даже не связанное с `.map`.

Решение: матчер называется `@borodatych_security_maps`; «уже настроено» определяется по
`path ... .map`, а не по имени матчера.

## nginx: однострочный server-блок

`server { listen 443 ssl; server_name example.ru; ... }` — валидный nginx. Старый код искал
перевод строки после `server_name`, не находил его внутри блока и дописывал `include` после
закрывающей `}`. Хуже того, в однострочном `location` include вставлялся без перевода строки,
и `#` в конце строки съедал остаток конфига.

Решение: позиция считается от `;` после `server_name`; если перевод строки находится за
пределами блока, include вставляется сразу после `;` и обязательно с `\n` в конце.

## reload без systemctl

В контейнерах `systemctl` нет. `fix` сначала пробует его, получает `reason = missing` и вызывает
`nginx -s reload` / `caddy reload`. Стенд проверяет не факт вызова, а результат: заголовки
появляются только после реальной перезагрузки. Если `systemctl` установлен, но не работает,
прямой путь не включается — это осознанно, чтобы не перезагружать сервер в обход службы.
